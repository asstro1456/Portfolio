03—1콘셉트와 제작 범위

콘텐츠를 편하게 감상하도록
패널형 갤러리로 바꿨습니다.

초기에는 책과 축음기를 찾아 CG와 엔딩, BGM을 감상하는 공간형 갤러리를 구상했습니다. 콘텐츠를 감상하는 과정에서도 공간을 탐색하는 재미와 분위기를 느끼게 하고 싶었습니다. 하지만 기능에 비해 개발과 아트 작업이 많이 필요했고, 이미 본 콘텐츠를 반복해서 감상할 때도 탐색 과정이 불편할 수 있다고 봤습니다.

팀의 피드백과 일정, 팀장이 제시한 방향을 반영하며 갤러리에서 우선해야 할 목적을 다시 생각했습니다. 수집한 콘텐츠를 빠르게 비교하고 감상할 수 있도록 공간형 원안은 폐기하고 패널형 UI로 바꿨습니다. 처음 구상했던 분위기는 프레임과 캡션에 반영해, 기능을 사용하는 데 필요한 과정은 줄이면서 콘셉트는 남기고자 했습니다.

폐기한 공간형 원안

책과 축음기를 찾아 탐색

탐색하는 분위기를 살릴 수 있지만, 개발과 아트 공수가 크고 반복 감상도 불편할 수 있었습니다.

패널형으로 범위 조정

콘텐츠를 빠르게 비교하고 감상

감상할 콘텐츠를 패널에서 확인하고, 공간의 분위기는 프레임과 캡션에 남겼습니다.

03—2화면 상태와 입력 조건

화면이 바뀌는 조건과 예외를 함께 정리했습니다.

화면 시안만으로는 어떤 입력을 받았을 때 다음 상태로 넘어가는지까지 전달하기 어렵습니다. 정비 공간에서는 적 정보와 덱 선택에 집중하도록 기능을 정리하고, 선택과 취소부터 패널 전환, 전투 진입까지의 조건을 유저 시나리오와 연결했습니다.

정상적인 흐름 외에도 데이터가 누락되거나 입력이 겹쳤을 때의 처리 기준을 문서화했습니다. 뒤로 가기 우선순위와 중복 입력, 저장, 초기화 조건을 구분하고, 내러티브에서는 입력 우선순위와 입력 소비 규칙을 명세했습니다. 같은 입력으로 여러 동작이 실행되거나 화면 상태가 충돌하는 일을 막기 위해, 어떤 처리가 우선인지 구현 기준에 포함했습니다.

01 / 의도

판단 범위 정하기

전투 준비에서 적 정보와 덱 선택에 집중하도록 기능을 정리했습니다.

02 / 상태

전환 조건 정하기

선택과 취소, 패널 전환, 전투 진입 조건을 유저 시나리오와 연결했습니다.

03 / 예외

누락과 충돌 다루기

데이터가 없을 때 사용할 기본값과 입력 처리 우선순위를 명세했습니다.

구현 기준을 담은 대표 명세 3건 펼치기

화면의 목적과 실제 입력 조건을 함께 확인할 수 있는 작업 자료입니다.

구현과 회고

정리한 화면 상태는 Figma 프로토타입과 Unity에서 전환을 확인했고, 시안을 uGUI에 배치하며 앵커를 조절했습니다. 갤러리의 범위를 바꾸면서, 의도한 경험을 만드는 데 필요한 작업량도 기획 초기에 함께 검토해야 한다고 생각했습니다. 다음에는 초기 프로토타입 단계에서 핵심 경험과 제작 비용을 함께 확인할 계획입니다. 기능의 목적에 비해 필요한 작업이 크다면, 상세 제작에 들어가기 전에 범위를 조정하려고 합니다.
