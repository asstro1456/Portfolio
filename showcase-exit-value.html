06—1데이터 관계 정리

각 데이터가 호출할 장면과 기능을 구분했습니다.

시나리오의 값과 참조 관계를 정리하며 테이블을 정규화하고 ERD를 작성했습니다. 대사와 인물, 배경, 사운드, 선택지가 어떤 관계로 연결되는지 문서에서 확인할 수 있도록 정리했습니다.

이 관계를 기준으로 시나리오 데이터를 연결하고 선택지와 저장, 연출 기능을 적용했습니다. 이야기의 진행을 데이터와 기능의 연결로 옮기는 작업이었습니다.

06—2엔진 적용과 확인

AI가 작성한 코드도 엔진에서 직접 확인했습니다.

AI가 작성한 MLua 코드의 참조 관계와 동작을 엔진에서 확인하며 오류를 수정했습니다. 코드와 엔진 경험이 적었던 만큼, 결과물을 어디에 적용해야 하고 어떤 데이터를 참조하는지 직접 찾아보는 데 시간이 들었습니다.

ERD와 테이블을 기준으로 기능을 연결했지만 디버깅 비용이 컸습니다. 엔딩 곡 영상은 Suno AI와 CapCut으로 제작했습니다. 이 작업을 통해 기능을 한꺼번에 연결하기 전에 작은 단위로 동작을 확인할 필요를 느꼈습니다.

구현 과정에서 남긴 과제

데이터 관계와 판정 조건을 먼저 문서화하고, 작은 기능부터 엔진에서 확인하는 순서로 작업하려고 합니다. AI가 만든 코드도 참조와 실행 위치를 이해한 뒤 적용해야 한다는 기준을 남겼습니다.

06—3이후의 구조 개선 구상

한 스크립트에 모인 책임을 나누는 설계를 구상했습니다.

메커톤을 준비하며 2,235줄과 72개 함수가 한 스크립트에 모인 VNScene을 다시 분석했습니다. 첫 구현에서 겪은 디버깅 부담을 바탕으로 VNHub를 중심에 두고, 스토리와 데이터, UI, 선택지, 상태, 저장, 연출의 책임을 나누는 아키텍처를 구상했습니다.

이 자료는 이후의 구조 개선을 위한 설계 구상입니다. 초기 게임에 적용한 기능과 구분해, 첫 구현에서 드러난 문제를 다음 설계에 어떻게 반영하려 했는지 보여줍니다.
