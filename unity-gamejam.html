시스템과 콘텐츠 기획

이동현

아이디어를 플레이 규칙과 화면의 동작 조건으로 정리합니다.

플레이어가 무엇을 보고 어떤 선택을 하게 할지 생각하며 시스템과 콘텐츠를 기획합니다. 팀 프로젝트에서는 규칙과 예외를 문서로 전달하고, Unity에서 실제 공간과 UI 상태를 확인했습니다. 개인 프로젝트에서는 웹 프로토타입을 만들어 규칙을 시험하고 플레이 기록을 살폈습니다.

핵심 규칙과 제작 범위를
팀과 함께 정하고 싶습니다.

게임잼에서는 제한된 시간 안에 어떤 경험을 먼저 완성할지 정하는 일이 필요하다고 생각합니다. 기획 역할로 참여해 핵심 플레이 흐름과 조작, 성공과 실패 조건을 정리하고, 팀이 구현할 범위를 함께 맞추고 싶습니다.

설명이 다르게 해석될 수 있는 부분은 입력 조건과 예외로 구분하겠습니다. 글만으로 전달하기 어려운 조작은 작은 프로토타입으로 확인하고, 구현 결과를 함께 보며 수정할 항목을 정리하겠습니다.

01팀 프로젝트 / Project UT

화면 시안에
동작 조건을 함께 붙였습니다.

비주얼 노벨 카드 게임의 전투 HUD와 갤러리, 내러티브, 정비 공간을 기획했습니다. 시안만으로는 어떤 입력을 받았을 때 화면이 바뀌는지까지 전달하기 어려워, 선택과 취소, 패널 전환, 입력 우선순위를 함께 정리했습니다.

데이터가 누락되거나 입력이 겹칠 때의 처리도 명세에 포함했습니다. 정리한 화면 상태는 Figma 프로토타입과 Unity에서 전환을 확인하고, 시안을 uGUI에 배치하며 앵커를 조절했습니다.

02팀 프로젝트 / Project BB

무작위 공간의 규칙을
실제 수치로 확인했습니다.

플레이어 조작과 몬스터 행동, 성장, 방 진행, 상점의 시스템 규칙을 정리했습니다. 방과 문, 복도가 무작위로 만들어지며 예외가 많아져, 맵 생성과 방 배치, 방 진행을 나눠 각 단계의 조건을 전달했습니다.

방에 들어오자마자 공격받는 상황을 줄이기 위해 Unity에서 실제 방 크기와 반경을 확인했습니다. 이를 바탕으로 반지름 4의 원형 입구 세이프 존을 적용했습니다. 문서의 수치와 실제 플레이 공간을 함께 확인한 경험입니다.

03개인 프로젝트 / Rune Trace

규칙을 프로토타입으로 만들고
입력 기록을 살폈습니다.

경로를 연결하는 퍼즐에 로그라이크 요소를 결합한 웹 프로토타입입니다. 경로를 판단할 시간을 주기 위해 실시간 디펜스에서 턴제로 바꾸고, 적을 처치한 경로에 흔적이 남아 다음 턴에 쓸 공간이 줄어들도록 규칙을 정했습니다.

처음 플레이한 외부 사용자의 로그에서 무효 입력이 반복되는 구간을 확인했습니다. 실패한 결과만으로 원인을 확정하지 않고, 입력 유형과 플로어, 재시도를 나눠 다음 테스트에서 비교할 항목을 정리했습니다. 이 프로젝트는 Unity 구현 사례가 아니라 규칙 설계와 프로토타입 검토 사례입니다.
