# 시스템 기획 프로젝트 요약

작성일: 2026-06-18  
범위: 현재 ChatGPT 프로젝트 `시스템 기획` 내부 대화 기준  
커밋 목적: 프로젝트 맥락, 확정 규칙, 진행 중인 설계 기준을 외부 저장소에 보존

---

## 1. 프로젝트 성격

이 프로젝트는 게임 기획 포트폴리오 개선을 중심으로, 시스템 기획, 콘텐츠 기획, UI/UX 설계, 데이터 테이블 구조화, 개발 협업 문서화를 다루는 작업 공간이다.

핵심 목적은 단순 아이디어 정리가 아니라, 취업용 포트폴리오에서 검증 가능한 기획 산출물을 만들기 위한 설계 기준을 정리하는 것이다.

## 3. 주요 확정 지침

### 3.1 프로젝트 요약 및 커밋 요청 처리

사용자가 다음과 같은 요청을 하면 기본 범위는 현재 ChatGPT 프로젝트 내부 대화로 한정한다.

- `프로젝트 대화 요약`
- `프로젝트 전문 요약`
- `마크다운으로 요약`
- `깃허브에 커밋`

단, 사용자가 명시적으로 `전체 프로젝트`, `다른 프로젝트 포함`, `크로스 프로젝트`라고 말하면 다른 프로젝트 대화까지 포함할 수 있다.

### 3.2 채팅 네이밍 규칙

향후 프로젝트 지침 초안에는 항상 채팅 네이밍 규칙을 포함한다.

권장 형식:

```text
[대분류] 작업 주제 - 핵심 산출물
```

예시:

```text
[시스템] 보상 수령 플로우 - 예외 케이스 정리
[UIUX] 카드 선택 화면 - Figma 구조 설계
[데이터] 아이템 테이블 - 컬럼 구조 검토
[협업] Git 충돌 처리 - 원인 및 규칙 정리
```

## 5. 시스템 기획 관련 확정 내용

### 5.1 플로우차트 사전 조건 표기

사전 조건은 일반 처리 블럭으로 넣기보다 `Preconditions`, `진입 조건`, `주석 박스`로 분리하는 것이 적절하다.

| 상황 | 권장 표기 |
|---|---|
| 로직 실행 전 만족되어야 하는 조건 | `Preconditions` 주석 박스 |
| 실행 시 조건을 검사하는 경우 | 마름모 판단 블럭 |
| 조건을 시스템이 세팅하는 경우 | 사각형 처리 블럭 또는 준비 블럭 |
| 변수 초기화/준비 단계 | 육각형 Preparation 블럭 사용 가능 |

권장 구조:

```text
[Preconditions]
- QuestState == Accepted
- FeatureUnlocked == true
- Cooldown == 0

↓

[Start]
↓
◇ 진입 조건 충족? ◇
 ├─ No → [사용 불가 안내]
 └─ Yes → [기능 실행]
```

핵심 판단:

- 조건을 설명만 하면 주석 박스
- 조건을 실제 검사하면 마름모
- 조건을 바꾸거나 세팅하면 처리 블럭
- 육각형은 사전 조건 자체보다 준비/초기화 단계에 가까움

## 6. Figma 및 Unity 연계 설계 기준

### 6.1 네이밍 규칙 방향

Figma 네이밍은 Unity 오브젝트와 연동될 수 있도록 과도하게 디자인 툴 중심으로 작성하지 않는다.

권장 원칙:

- 화면 단위, 패널 단위, 기능 단위를 구분한다.
- Unity에서 GameObject로 옮겼을 때 의미가 유지되어야 한다.
- 프리팹으로 묶일 상위 오브젝트는 명확한 기능명을 가진다.
- 하위 레이어는 실제 제어 대상인지, 단순 시각 요소인지에 따라 네이밍 강도를 조절한다.

예시 방향:

```text
Canvas_Battle
Panel_PlayerStatus
Prefab_CardSlot
Btn_TurnEnd
Txt_CardName
Img_CardIcon
Gauge_HP
```

### 6.2 Figma 학습 상태 요약

| 항목 | 현재 상태 |
|---|---|
| Component / Instance | 기본 사용 가능, 스왑과 구조 관리 학습 중 |
| Variants | 상태 전환 개념 이해, 실전 설계 추가 필요 |
| Variables | 개념 이해 시작, 모드/토큰 활용은 추가 학습 필요 |
| Auto Layout | 사용 경험 있음, padding/spacing/resize 기준 혼란 존재 |
| Constraints | 사용 경험 있음, 정확한 동작 기준 보완 필요 |
| Prototype | 기본 연결 가능, Smart Animate 조건과 오버레이 구조 보완 필요 |
| Dev Mode | 미사용에 가까움, 개발 핸드오프 기준 학습 필요 |

## 7. Git/GitHub 협업 관련 정리

### 7.1 Git ignore 처리 기준

Unity 프로젝트에서 특정 Figma 연동 파일과 임시 산출물을 제외하려는 요구가 있었다.

제외 대상으로 논의된 예시:

```text
ProjectUT/Assets/Figma/
ProjectUT/Assets/aa.unity
ProjectUT/Assets/aa.unity.meta
ProjectUT/Assets/Figma.meta
ProjectUT/Assets/FigmaOutput.json
ProjectUT/Assets/FigmaOutput.json.meta
ProjectUT/Assets/UnityFigmaBridgeSettings.asset
ProjectUT/Assets/UnityFigmaBridgeSettings.asset.meta
ProjectUT/UnityFigmaBridgeEditor.csproj
ProjectUT/UnityFigmaBridgeRuntime.csproj
```

주의점:

- Unity `.meta` 파일은 일반적으로 함부로 삭제하면 안 된다.
- 에셋 참조 GUID가 깨질 수 있다.
- 이미 Git에 추적 중인 파일은 `.gitignore`에 추가해도 자동 제외되지 않는다.
- 추적 해제가 필요하면 `git rm --cached` 계열 처리가 필요하다.

### 7.2 Merge / Rebase / Conflict 관련 기준

정리된 판단:

- 자동 머지가 안 되는 이유는 같은 파일의 같은 영역 수정, 바이너리 파일 충돌, Unity scene/prefab 충돌 등이 대표적이다.
- Rebase 커밋은 브랜치 기준점을 재배치하면서 커밋 이력이 다시 쓰이는 상황을 이해해야 한다.
- LF/CRLF 경고는 줄바꿈 규칙 문제이며, `.gitattributes`로 프로젝트 단위 규칙을 고정하는 편이 안전하다.

## 8. 스프레드시트 및 상태 관리 관련 정리

### 8.1 조건부 서식

요구사항:

- J열 값이 `종료`이면 해당 행 전체 색상이 변경되어야 함.

일반 구조:

```text
적용 범위: A:Z 또는 필요한 전체 범위
사용자 지정 수식: =$J1="종료"
```

핵심:

- 열 고정은 `$J`
- 행 번호는 적용 범위 시작 행에 맞춘다.
- 전체 열에 적용하려면 적용 범위를 충분히 넓게 잡아야 한다.

### 8.2 버그 리포트 상태값

버그 리포트 처리 상태에는 `Git Issue 등록` 또는 이에 준하는 상태가 필요하다고 판단했다.

상태 예시:

```text
신규
확인 중
재현 완료
수정 중
Git Issue 등록
수정 완료
검수 완료
종료
보류
```

주의점:

- `Git Issue 등록`은 버그가 해결되었다는 뜻이 아니라 추적 시스템에 등록되었다는 중간 상태다.
- 종료 상태와 혼동되지 않도록 워크플로우상 위치를 분리해야 한다.

## 9. 자료 조사 프로젝트 설계 기준

게임 포트폴리오 자료 조사용 프로젝트는 검색 전에 모호한 부분을 먼저 정리하도록 설계한다.

확인해야 할 항목:

- 조사 목적
- 대상 게임/장르/시장
- 필요한 자료 유형
- 신뢰도 기준
- 필요한 양과 깊이
- 커뮤니티 자료 허용 여부
- 결과물 형식

자료 유형 예시:

| 자료 유형 | 사용 목적 |
|---|---|
| 개발자 인터뷰 | 설계 의도, 업데이트 방향 파악 |
| 공식 공지 | 시스템 변경 근거 확인 |
| 패치노트 | 밸런스 변화 추적 |
| 유저 커뮤니티 | 실제 반응, 불만, 플레이 패턴 확인 |
| 매출/시장 자료 | 사업성 분석 보조 |
| 공신력 있는 기사/리포트 | 외부 근거 확보 |
