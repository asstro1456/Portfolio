# Portfolio Coach 후속 탭 질문지 Codex 답변

## 1. 전체 판단

- 질문지의 방향은 맞다. 후속 탭을 임의로 꾸미기 전에 실제 코드의 탭 역할, 입력 데이터, 출력 데이터, Figma 현재 상태를 먼저 고정해야 한다.
- 실제 코드 기준 탭은 `정보 입력`, `서류 피드백`, `포트폴리오`, `공고 분석`, `추천 공고`, `면접 대비`, `면접 기본 준비`, `인성검사`, `PDF 출력`으로 구성된다.
- 후속 Revision 대상 8개 탭은 대부분 실제 코드 기능과 맞춰 재정리해야 한다.
- `Desktop / 정보 입력 - Revision`은 기본 화면 기준이 잡혔으므로, 후속 탭도 같은 네비게이터, 같은 1120px 본문 폭, 같은 카드/섹션 밀도를 기준으로 맞추는 것이 좋다.
- 현재 Figma의 기존 후속 탭은 일부가 예전 UX/UI 디자이너 예시 또는 장식형 목업에 가까워, 실제 서비스 흐름 기준으로 재배치가 필요하다.
- 이번 GPT/Figma 작업 범위는 **사이트 코드나 비즈니스 로직 수정이 아니다.** 실제 코드 구조는 화면 정보 설계의 참고 기준으로만 사용한다.
- GPT/Figma 작업자는 **Figma 안의 인터랙션 표현, 탭 전환 상태, 컴포넌트 배치, UI 레이아웃, 가독성 정리만 수행한다.**
- 코드에 없는 새 기능을 Figma에 넣어야 할 경우에는 “구현 예정”처럼 보이게 만들지 말고, 먼저 사용자에게 확인한다.

## 2. 코드 기준 공통 데이터 흐름

```text
정보 입력
→ 사용자 프로필, 직군/세부 직무, 경력, 스킬, 자기소개, 이력서/자소서/포트폴리오 파일, 우선 공고, 강사 피드백 입력
→ AI 분석 실행
→ results 생성
→ 서류 피드백 / 포트폴리오 / 면접 대비 / PDF 출력에서 results 재사용

공고 분석
→ 수집된 GameJob 공고 데이터와 히스토리 분석
→ 시장/공고 흐름, 직군 분포, 경력 분포, 키워드, 스킬 매트릭스 표시

추천 공고
→ 사용자 프로필과 수집 공고를 매칭
→ 점수, 점수 breakdown, AI Match Reason, 강점/주의점, 회사 정보 액션 표시

면접 기본 준비
→ 직군별 고정 playbook 데이터 표시
→ 복장/시간/태도/마인드셋/답변 프레임 중심

인성검사
→ 연습 문항, Likert 본검사, A/B 선택 문항, 결과 분석
→ AI 또는 로컬 fallback 분석 결과 표시

PDF 출력
→ 프로필, 추천 공고, 강점/보완점, 서류 피드백, 포트폴리오/GitHub, 강사 피드백을 출력용 문서로 묶음
```

## 3. 탭별 실제 기능 요약

| 탭 | 실제 역할 | 주요 입력 | 주요 출력 | 다음 탭으로 넘기는 데이터 |
|---|---|---|---|---|
| 서류 피드백 | 이력서/자소서/우선 공고 기준 개선점 표시 | `results.resumeImprovements`, `results.coverLetterImprovements`, 추천 공고, 스킬 | 이력서 개선, 자소서 공통 개선, 공고별 맞춤 피드백, 분석 히스토리 | 포트폴리오/면접/PDF에서 재사용되는 `results` |
| 포트폴리오 | 포트폴리오 문서와 GitHub 분석 결과 표시 | `portfolioFiles`, `results.portfolioImprovements`, `results.githubPortfolioAnalysis` | 수정 우선순위, 검토 기준, GitHub 기술 문서화, 제출 패널 | PDF 출력, 면접 대비에서 활용 가능 |
| 공고 분석 | 수집 공고 전체의 시장/직군/경력/키워드 흐름 분석 | `jobs`, `jobsMetadata`, `jobs-history-index.json` | 시장 요약, 공고 분포, 경력 분포, 키워드 클라우드, 스킬 매트릭스, 공고 목록 | 추천 공고의 후보 데이터 이해 |
| 추천 공고 | 사용자 프로필 기준 공고 매칭 | `userInfo`, `jobs`, `candidateJobs`, `matchedJobs` | 매칭 점수, AI Match Reason, 강점/주의점, 점수 breakdown, 공고 링크, 회사 정보 | 서류 피드백 맞춤 항목, 면접 대비 대상 |
| 면접 대비 | 추천 공고 Top 기준 회사별 예상 질문/답변 방향 표시 | `results.interviewPreps` | 회사별 질문, 피해야 할 답변, 권장 답변, 인재상/과제 대비 | PDF 출력에 간접 반영 |
| 면접 기본 준비 | 면접 당일/기본 태도/답변 프레임 체크리스트 | `ROLE_READINESS_PLAYBOOK`, `interviewBasicData` | 빠른 체크, 답변 프레임, 면접관 시선, 준비 항목 | 별도 저장 데이터 없음 |
| 인성검사 | 실제 응답형 검사와 결과 해석 | Likert 답변, A/B 답변, 사용자 직군 | 성향 점수, 업무 스타일, 일관성, 강점/주의점, 다운로드/프린트 | 면접 준비 참고 자료 |
| PDF 출력 | 분석 결과를 출력용 문서로 변환 | `results`, `userInfo`, `recommendedJobs`, `instructorFeedback` | 브라우저 인쇄 기반 PDF 리포트 | 외부 공유/제출물 |

## 4. 탭별 권장 화면 구조

### 4-1. 서류 피드백

```text
Header message:
- “기획 서류 피드백” 또는 직군별 playbook title
- 현재 분석 기준: 지원 직무, 우선 공고, 강하게 연결되는 역량

Summary cards:
- 현재 검토 기준
- 우선 연결 공고 Top 3
- 강하게 연결되는 역량

Main feedback section:
- 이번 수정에서 먼저 볼 항목
- resultPlaybook.feedbackCards 기반 3개 원칙 카드

Priority fix list:
- 이력서 개선점
- 자기소개서 공통 개선점

Detail feedback area:
- 우선 공고가 지정된 경우 rank1/rank2/rank3 맞춤 피드백
- 분석 히스토리 패널

CTA:
- 정보 입력으로 돌아가기
- PDF 출력으로 이동
```

Figma 수정 포인트:
- 현재 `Desktop / 서류 피드백 - Revision`은 점수 중심 목업에 가깝다.
- 실제 코드에는 “75점/섹션별 점수” 구조가 핵심이 아니다.
- 점수 패널보다 `수정 우선순위`, `이력서`, `자소서`, `공고별 맞춤 피드백`, `분석 히스토리`를 중심으로 재구성해야 한다.

### 4-2. 포트폴리오

```text
Header message:
- “기획 포트폴리오 설계”
- 포트폴리오를 채용자가 읽을 수 있는 실무 언어로 정리한다는 메시지

Portfolio summary:
- 첨부 자료 수
- 수정 항목 수
- GitHub 분석 연결 여부

Project evidence review:
- 포트폴리오별 개선점 목록
- 파일명 기반 피드백 row

Missing proof / weak proof:
- 역량 증거가 약한 부분
- 구조/설명/전달력 보완점

Recommended restructuring:
- resultPlaybook.portfolioCards 기반 검토 기준

CTA:
- 포트폴리오 제출 저장
- PDF 출력으로 이동
```

Figma 수정 포인트:
- 기획 트랙 기준에서는 GitHub가 없어도 포트폴리오 탭이 성립한다.
- GitHub 분석은 프로그래밍 트랙 중심 조건부 섹션으로 처리한다.
- 기본 화면에는 PDF/문서 포트폴리오 개선 우선순위와 프로젝트 증거 구조가 먼저 보여야 한다.
- GitHub 카드가 기본 기획 화면 중심에 크게 들어가면 안 된다.

### 4-3. 공고 분석

```text
Header message:
- “수집된 게임 공고 시장 흐름”
- 현재 수집 범위, 마지막 성공 시각, 활성 공고 수 표시

Job summary:
- 전체 공고 수
- 최신 반영일
- 신규 공고 수
- 활성 공고 수

Requirement breakdown:
- 직군 분포
- 경력 분포
- 장르/키워드 분포

Fit / gap analysis:
- 현재 트랙 기준 주요 요구 스킬
- 상위 회사/상위 키워드

Keyword extraction:
- 키워드 클라우드
- 스킬 매트릭스

Next action:
- 추천 공고 탭에서 개인 프로필 기준 매칭 실행
```

Figma 수정 포인트:
- 공고 분석은 사용자가 입력한 특정 공고 1건 분석 화면이 아니다.
- 실제 코드는 수집 공고 전체를 시장 데이터처럼 분석한다.
- 추천 공고 탭과 겹치지 않게 “시장/분포/트렌드/목록 필터” 역할로 분리해야 한다.

### 4-4. 추천 공고

```text
Header message:
- “기획 적합 공고 탐색”
- 수집 공고를 개인 프로필 기준으로 매칭한다는 메시지

Filter / sort controls:
- 검색어
- 점수 구간 필터: 전체, 90+, 80+, 70+, 60+, 60-

Job match cards:
- 회사명
- 공고명
- 직군
- 경력
- 요구 스킬
- 공고 URL
- 공고 바로가기
- 회사 정보 보기

Score breakdown:
- 직군 15
- 경력 15
- 스킬 30
- 정합도 25
- 복수매칭 15

AI match reason:
- AI Match Reason
- 강점 사인
- 주의 사인

Save / pin action:
- 현재 코드상 추천 결과 카드에는 저장/핀 액션이 직접 있지 않다.
- 우선 공고 지정은 정보 입력 탭의 Pinned Job Slot 흐름과 연결되는 개념으로 보는 것이 맞다.
```

Figma 수정 포인트:
- 추천 공고 카드는 실제 데이터 필드에 맞춰야 한다.
- “AI Match Reason”은 코드와 데이터에 존재한다.
- 점수 breakdown도 코드에 존재하므로 화면에 표시 가능하다.
- 공고 저장/핀 버튼을 넣고 싶다면 현재 코드와는 차이가 있으므로 “향후 기능”으로 표시해야 한다.

### 4-5. 면접 대비

```text
Header message:
- 추천 공고 기반 회사별 면접 준비

Interview question groups:
- 회사별 탭
- rank / company 기준 전환

Priority questions:
- 회사별 예상 질문
- 직무/산업/프로젝트 관련 질문

Answer draft area:
- 현재 코드에는 사용자가 답변을 직접 입력하고 피드백받는 기능은 없다.
- 답변 입력 영역은 넣지 않는 것이 맞다.

Feedback / coaching area:
- 피해야 할 답변
- 권장 답변 방향
- STAR / BLUF 답변 프레임

CTA:
- 추천 공고로 돌아가기
- PDF 출력으로 이동
```

Figma 수정 포인트:
- “질문 생성 + 답변 코칭 방향” 중심이다.
- 실시간 답변 입력/피드백 화면처럼 만들면 실제 코드와 어긋난다.
- 기본 화면에는 예시 질문 2개 정도가 적절하다. 너무 많이 노출하면 포트폴리오형 UI가 아니라 문제은행처럼 보인다.

### 4-6. 면접 기본 준비

```text
Header message:
- 직군별 면접 기본 준비 메시지

Basic preparation checklist:
- 복장
- 시간
- 태도
- 마인드셋

Company research checklist:
- 회사/공고 확인
- 지원 직무 기준 정리

Day-before checklist:
- 전날 준비물
- 답변 프레임 재확인

Interview day checklist:
- 면접 직전 5분 체크
- 면접관 시선으로 보는 답변 기준
```

Figma 수정 포인트:
- 면접 대비 탭과 다르게, 특정 회사별 예상 질문이 아니라 기본 체크리스트 화면이다.
- 별도 AI 결과가 없어도 항상 표시 가능한 탭이다.
- 사용자가 입력하는 화면보다 “준비 가이드/체크리스트”로 구성해야 한다.

### 4-7. 인성검사

```text
Header message:
- 응답 성향을 직군 맥락으로 해석한다는 메시지

Readiness guide:
- 연습 5문항
- 본검사 94문항
- 선택형 31문항
- 총 40분

Common risk patterns:
- 과도한 미화 응답
- 일관성 낮은 응답
- 직군별 리스크

Practice questions:
- 연습 화면
- Likert 본문
- A/B 선택 문항

Consistency checklist:
- 응답 분포
- 일관성 점수
- 업무 스타일 축

CTA:
- 연습 시작
- 본검사 시작
- AI 분석 요청
- 다시 시작
- Markdown/PDF 출력
```

Figma 수정 포인트:
- 실제 검사 기능이다. 단순 준비 가이드만은 아니다.
- 다만 기본 Revision 화면은 검사 앱처럼 과하게 보이기보다 “취업 준비용 성향 해석 도구”로 신뢰감 있게 보여야 한다.
- 문항 화면, 결과 화면은 상태 예시로 분리하는 것이 좋다.

### 4-8. PDF 출력

```text
Header message:
- 분석 결과를 하나의 출력 리포트로 묶는 화면

Export target selection:
- 현재 코드에는 사용자가 섹션을 직접 선택하는 기능은 없다.
- 포함 섹션 목록을 보여주는 구조다.

Report preview:
- 출력 상태 카드
- 파일명
- 출력 방식
- 포함 범위

Included sections checklist:
- 프로필 요약
- 추천 공고 Top 3
- 강점/보완 사인
- 이력서 피드백
- 자기소개서 피드백
- 포트폴리오/GitHub 메모
- 강사 피드백

Export CTA:
- PDF 리포트 저장 버튼
- 브라우저 인쇄 창 기반 출력
```

Figma 수정 포인트:
- “미리보기 + 선택 체크박스”처럼 만들면 실제 구현보다 앞선 화면이 된다.
- 지금 기준은 포함 섹션을 보여주고, 버튼으로 브라우저 인쇄 창을 여는 구조다.
- 섹션 선택 기능은 향후 개선안으로만 표시한다.

## 5. Figma 수정 우선순위

### P0

```text
가장 먼저 정리해야 할 탭:
- 서류 피드백
- 포트폴리오
- 추천 공고

이유:
- 정보 입력 다음 사용자 흐름에서 바로 이어지는 핵심 결과 화면이다.
- 사용자가 취업 준비에서 직접 도움을 받는 가치가 가장 크다.
- 현재 Figma가 실제 코드 데이터 구조와 어긋나는 부분이 많다.

수정 범위:
- 예전 점수/디자인 목업 제거
- 실제 results 구조 기반으로 카드/리스트 재배치
- 추천 공고 카드에는 점수 breakdown과 AI Match Reason 반영
- GitHub 섹션은 포트폴리오 기본 화면에서 조건부/보조 섹션으로 낮춤
```

### P1

```text
다음으로 정리할 탭:
- 공고 분석
- 면접 대비
- PDF 출력

이유:
- 공고 분석은 추천 공고와 역할 분리가 필요하다.
- 면접 대비는 추천 공고 결과와 연결되므로 P0 이후 정리해야 정확하다.
- PDF 출력은 앞선 결과 화면 구조가 확정되어야 포함 섹션이 흔들리지 않는다.

수정 범위:
- 공고 분석은 시장/분포/트렌드 탭으로 재정의
- 면접 대비는 회사별 예상 질문과 답변 방향 중심으로 정리
- PDF 출력은 선택형 설정 화면이 아니라 출력 상태/포함 범위/저장 CTA 화면으로 구성
```

### P2

```text
나중에 정리해도 되는 탭:
- 면접 기본 준비
- 인성검사

이유:
- 면접 기본 준비는 고정 playbook 기반이라 핵심 데이터 의존도가 낮다.
- 인성검사는 기능 범위가 크지만, 후속 탭의 취업 지원 핵심 흐름에서는 P0/P1 이후로 밀어도 된다.

수정 범위:
- 면접 기본 준비는 체크리스트/가이드 형태로 정리
- 인성검사는 intro/test/result 상태를 분리하고, 기본 화면은 신뢰감 있는 안내 화면으로 구성
```

## 6. GPT/Figma 작업자에게 넘길 구체 수정 요청

```markdown
아래 기준으로 후속 탭 Revision 프레임을 정리해줘.

0. 작업 범위 제한
   - 이 작업은 사이트 코드나 실제 로직을 수정하는 작업이 아니다.
   - 코드 구조는 Figma 화면 정보 설계를 맞추기 위한 참고 기준으로만 사용한다.
   - Figma 안에서 인터랙션 표현, 탭 상태, 버튼/카드 배치, UI 레이아웃, 텍스트 가독성만 정리한다.
   - 실제 서비스 로직 변경, 새 기능 추가, 데이터 구조 변경처럼 보이는 화면은 만들지 않는다.

1. 후속 탭은 `Desktop / 정보 입력 - Revision`의 구조를 기준으로 맞춘다.
   - Navigator는 정보 입력 Revision에서 쓰는 Navigator 인스턴스 기준을 유지한다.
   - 본문 폭은 1120px 기준으로 맞춘다.
   - 기본 화면에는 실제 사용자가 보는 UI만 남긴다.

2. P0으로 먼저 정리할 탭은 `서류 피드백`, `포트폴리오`, `추천 공고`다.
   - 서류 피드백은 점수 중심 목업이 아니라 이력서/자소서/공고별 맞춤 피드백 구조로 바꾼다.
   - 포트폴리오는 PDF/문서 포트폴리오 개선 우선순위를 기본으로 두고, GitHub 분석은 조건부/보조 섹션으로 낮춘다.
   - 추천 공고는 회사명, 공고명, 직군, 경력, 요구 스킬, 점수, 점수 breakdown, AI Match Reason, 강점/주의점, 공고 링크를 포함한다.

3. P1 탭은 `공고 분석`, `면접 대비`, `PDF 출력`이다.
   - 공고 분석은 특정 공고 1건 분석이 아니라 수집 공고 전체의 시장/분포/트렌드 화면이다.
   - 면접 대비는 답변 입력 화면이 아니라 추천 공고 Top 기준 회사별 예상 질문과 피해야 할 답변/권장 답변 방향을 보여준다.
   - PDF 출력은 섹션 선택 기능이 아니라 현재 포함 가능한 결과와 PDF 저장 CTA를 보여준다.

4. P2 탭은 `면접 기본 준비`, `인성검사`다.
   - 면접 기본 준비는 복장/시간/태도/마인드셋/회사 조사 체크리스트 중심이다.
   - 인성검사는 실제 검사 기능이므로 intro/test/result 상태를 구분하되, 기본 Revision은 신뢰감 있는 안내 화면으로 둔다.

5. 기존 Figma에서 실제 코드와 맞지 않는 요소는 제거하거나 낮춘다.
   - 예전 UX/UI 디자이너 예시 프로젝트 카드
   - 실제 코드에 없는 섹션 선택형 PDF 설정
   - 실제 코드에 없는 답변 입력형 면접 피드백
   - 기본 기획 화면의 중심 콘텐츠로 보이는 GitHub 카드
   - 점수만 강조하는 서류 피드백 목업

6. 텍스트 가독성 기준을 지켜줘.
   - 깨진 문자처럼 보이는 placeholder나 임시 텍스트를 남기지 않는다.
   - 텍스트와 버튼이 겹치지 않게 한다.
   - 상태명(`empty`, `uploaded`, `default`)은 기본 화면에 노출하지 않는다.
   - 점선/가이드 레이어는 실제 UI로 오해되지 않게 `Guide / ...`로 명명하거나 숨긴다.

7. 컴포넌트 사용 기준을 지켜줘.
   - 준비된 컴포넌트만 사용한다.
   - 새 컴포넌트가 필요하면 만들기 전에 먼저 질문한다.
   - 상태 예시는 `02. component > Input Workspace Components / State Examples`에만 둔다.
   - Mobile / Tablet 프레임은 새로 만들지 않는다.

완료 후에는 탭별로 수정한 섹션, 제거한 레이어, 아직 코드 확인이 필요한 항목을 짧게 보고해줘.
```

## 7. 추가로 확인 필요한 코드/데이터

- Figma 각 후속 Revision 프레임은 전체 시각 검토가 추가로 필요하다. 현재 판단은 Figma 메타데이터와 코드 구조 기준이다.
- 저장소 코드에 일부 한글 인코딩 깨짐이 보인다. 실제 서비스 화면에서도 깨져 보이면 Figma 이전에 코드 텍스트 복구가 필요하다.
- 추천 공고의 “저장/핀” 액션은 현재 추천 카드 자체보다 정보 입력의 Pinned Job Slot 흐름과 연결된다. GPT가 카드 안에 저장 버튼을 넣으려면 향후 기능으로 명시해야 한다.
- PDF 섹션 선택 기능은 현재 코드에 없다. Figma에 넣으면 구현 예정 기능처럼 보이므로 지금은 제외하는 것이 맞다.
