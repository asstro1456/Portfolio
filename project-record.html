RUNE TRACE · 2026.07.24 — 07.29

플레이 로그를 모아 규칙의 개선 방향을 정했습니다

역할
시스템·콘텐츠·UX·밸런스·로그 기획
범위
7×7 보드 · 9플로어 · 능력 6종 · 보스 변형 3종
산출물
웹 프로토타입 · 규칙·밸런스 문서 · 자동 플레이 로그

장르 선택과 규칙 발전

짧고 단순한 입력 안에 여러 판단을 만들기 위해 경로 연결형 퍼즐과 로그라이크를 결합했습니다. 경로로 적을 처치하면 흔적이 남아 다음 룬의 공간을 줄이도록 해, 현재의 공격이 미래 행동의 비용이 되게 했습니다. 실시간 디펜스는 시간 압박이 경로 판단을 방해해 턴제로 바꿨고, 무작위 이동·오염은 행동 전에 공개해 결과를 읽고 결정할 수 있도록 수정했습니다.

프로토타입과 로그 검증

제 플레이를 제외하고, 처음 플레이한 외부 사용자의 로그를 기록했습니다. 입력 유형·플로어·재시도 기준으로 결과를 나눠 규칙 이해 문제와 전략적 실패를 구분할 검증 계획을 세웠습니다. 다음 검증 항목은 정식 튜토리얼 적용 전후의 입력 실패율·클리어율 비교입니다. 표본이 작아 재미나 시장 성과를 판단하기는 어렵습니다. 입력 과정에서 어려움이 생기는 지점을 찾는 초기 자료로 사용합니다.

문제 발생
플레이 로그에서 무효 경로 입력과 재시도가 반복됐습니다.
발생 원인
회전·반전과 경로 완성 조건을 플레이 중 충분히 학습시키지 못했을 가능성이 있습니다.
결과
입력 유형·플로어·재시도 구간을 분리해 입력에 어려움이 생긴 조건을 확인했습니다.
추후 대처법
튜토리얼 적용 전후의 무효 입력률·클리어 시간·재시도를 같은 기준으로 비교합니다.

NYANGNYANGSTAR · 2026.05.04 — 07.16

유저마다 다른 피드를 만드는 콘텐츠를 제안했습니다

역할
시스템 기획
협업
기획 8명 · 개발 4명 · 약 2.5개월
산출물

문제와 판단

냥냥스타는 머지 플레이와 골드를 사용하는 건설 요소를 갖추고 있었지만, 스토리를 전달하는 피드의 콘텐츠는 부족했습니다. 사용자마다 다른 피드 경험을 만들기 위해 UGC형 가상 유저 피드를 제안했습니다. 자유 스크린샷 공유는 기업 요구·서버 비용·개발 난이도를 고려해 게임에서 얻은 CG를 편집하는 방식으로 축소했지만, 다른 유저가 이미지를 볼 수 있는 구조는 유지했습니다.

실행과 협업

금지어 처리 부담을 줄이고 기존 머지의 드래그 조작을 활용하기 위해 단어 블록 조합 방식을 설계했습니다. 글로만 조작 방식을 전달하기 어려워 HTML 프로토타입을 만들고, 블록 배열·중복 제한·드래그 취소·자동 스크롤 등 구현 조건을 검수했습니다. 기업 피드백이 이틀 늦어지며 시스템 절반을 다시 설계했습니다. 상세 명세 전달이 늦었던 원인은 별도로 회고하고, 드래그 오류는 QA 이슈로 계속 추적했습니다.

문제 발생
일부 조작과 UI가 의도한 방식으로 구현되지 않았습니다.
발생 원인
상세 명세 전달과 기업 피드백이 늦어 시스템 절반을 다시 설계했습니다.
결과
드래그 오류를 반복 추적했지만 초기 기능 일부는 범위에서 제외됐습니다.
추후 대처법
핵심 규칙·예외·UI 설계 이유를 먼저 정리하고, 외부 피드백을 반영할 시간을 일정에 확보합니다.

PROJECT UT · 2026.04.30 — 진행 중

역할
콘텐츠·시스템 기획 · UI 상태·연출 명세
범위

산출물

문제와 판단

기능을 사용할 때도 세계관과 설정이 드러나는 UI를 만들고자 했습니다. 정비 공간에는 덱을 빠르게 결정·확인하는 기능과 바 콘셉트를 결합했습니다. 초기 갤러리는 유저가 책과 축음기를 탐색해 CG·엔딩·BGM을 감상하는 공간형 콘텐츠였지만, 일정 대비 개발·아트 공수가 크고 반복해서 감상할 때 불편할 수 있었습니다.

실행과 협업

팀 피드백과 일정, 팀장의 방향을 반영해 공간형 갤러리는 폐기하고 패널형 UI로 전환했습니다. 콘텐츠를 빠르게 비교·감상하는 목적은 유지하고, 공간형 콘셉트의 분위기는 프레임과 캡션에 반영했습니다. 데이터 누락·뒤로 가기 우선순위·중복 입력·저장·초기화 등 예외 조건을 문서화하고 Figma와 Unity에서 상태 전환을 확인했습니다.

문제 발생
책상·축음기를 탐색하는 공간형 갤러리를 적용하지 못했습니다.
발생 원인
기능 대비 개발·아트 공수가 컸고 팀의 일정과 방향을 맞춰야 했습니다.
결과
콘텐츠를 빠르게 확인하는 패널형 UI로 범위를 조정했습니다.
추후 대처법
핵심 경험과 제작 비용을 초기 프로토타입 단계에서 함께 검증합니다.

역할

문제와 판단

실행과 협업

초기 콘셉트와 전체 플로우를 정리한 뒤, 공통 용어와 플레이어 조작·판정부터 몬스터 행동·성장·방 진행·상점·데이터 테이블까지 개발자가 참조할 수 있는 기획서로 구체화했습니다. 이미지는 전·후·측면의 기본 형태를 먼저 정한 뒤 공격·대기·걷기·보스 시트로 발전시키고 Aseprite에서 리터칭했습니다. 컷신은 AI 초안을 만든 뒤 경고 오버레이와 분리 리소스를 추가하고, PSD에서 수정해 최종 장면으로 다듬었습니다.

문제 발생

발생 원인
방·문·복도 생성 규칙이 함께 무작위로 작동해 예외 조합이 많았습니다.
결과

추후 대처법

문제와 판단

다른 팀원이 제안한 세계관을 존중하면서도, 팀이 목표로 둔 힐링 감성에 맞는 시나리오를 써야 했습니다. 삼족오·국악·거문고의 의미를 엮어 조선 국악 판타지를 구상했으나, 분량이 길고 팀이 원하는 방향과도 멀다는 피드백을 받았습니다.

실행과 협업

팀이 합의한 핵심 감정과 출시 가능한 분량을 기준으로 설정을 줄였습니다. 시나리오를 압축하고, 매일 10분씩 진행 상황을 공유하며 역할별 작업을 확인했습니다. 곡의 템포와 스테이지 난이도를 서사의 긴박도와 연결하고, 시대 고증을 다시 확인해 배경 시대와 복장·분위기를 조정했습니다.

문제 발생
시나리오가 목표한 힐링 방향과 멀고 분량도 길어졌습니다.
발생 원인
기존 세계관을 살리려다 조선 국악 판타지 설정을 과도하게 확장했습니다.
결과
설정 일부를 폐기하고 5개 스테이지의 게임을 일정 안에 완성했습니다.
추후 대처법
목표 정서·분량·완료 기준을 먼저 합의하고 중간 검토에서 범위를 조정합니다.
